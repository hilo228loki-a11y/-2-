## 1. Цель и постановка задачи
Освоить обработку данных, превышающих объём ОЗУ, на примере внешней сортировки; реализовать её на C++ и Python, сравнить.
Требования: файл data.csv > 1 ГБ; выбор ключа; память ≤ 10 % размера файла; удаление временных файлов;
замер времени разбиения и слияния; общее время ≤ 10 мин; GUI с генерацией, выбором файла и проверкой результата.
Предметная область: сотрудники, поля `id,name,city,age,salary,date` (согласовать с преподавателем).

## 2. Алгоритм внешней сортировки (двухфазное сортирующее слияние)
1. **Разбиение (split).** Файл читается блоками, размер блока выбран так, чтобы вместе с накладными расходами структур данных укладываться в лимит памяти. Блок сортируется в ОЗУ и записывается во временный файл — «серию» (run).
2. **Слияние (merge).** Все k серий открываются одновременно, из первой строки каждой серии строится двоичная куча (min-heap). Из кучи извлекается минимальный элемент, пишется в выходной файл, на его место добавляется следующая строка той же серии.
3. Временные файлы удаляются. Сложность: O(N log N) по сравнениям, O(N) дискового ввода-вывода за 2 прохода (чтение+запись на каждой фазе).

## 3. Реализация
**Python (`external_sort.py`)**: `with open(...)`, `f.readlines(sizehint)` — чтение блоками, `csv.reader`/`csv.writer`, `sorted(range(n), key=keys.__getitem__)` — сортировка индексов по списку ключей, `heapq.merge` — k-путевое слияние, `ExitStack` — открытие k файлов, `tempfile.mkdtemp` + `shutil.rmtree` в `finally` — временные файлы, автоопределение типа ключа (int/float/str).
**C++ (`external_sort.cpp`)**: `std::ifstream/ofstream` с буферами 1–4 МБ через `pubsetbuf`; `struct Item{Key,line}`; `std::sort` блока; `std::vector<Node>` + `push_heap/pop_heap` (min-куча, элементы перемещаются `std::move`); `items.reserve` исключает удвоение capacity; `std::filesystem::file_size` для расчёта лимита; `std::remove` для временных файлов.
**Генератор (`generator.py`)**: пачки по 100 000 строк через `random.choices`, запись одним `write` на пачку.
**GUI (`gui.py`, tkinter)**: генерация (импорт модуля, отдельный поток), выбор файла и ключа, запуск сортировки подпроцессом (интеграция через командную строку и вывод `KEY=VALUE`), просмотр начала/конца файла и проверка порядка по всему файлу.

## 4. Результаты (файл 1103 МБ, 20,7 млн строк, ключ salary, лимит памяти 110 МБ)
| Реализация | Серий | Разбиение, с | Слияние, с | Всего, с | Пик ОЗУ, МБ |
|---|---|---|---|---|---|
| C++ (-O2) | 36 | 16,6 | 8,9 | 25,4 | 88 |
| Python | 50 | 34,5 | 82,8 | 117,3 | 97 |

*Замеры выполнены в тестовой среде (Linux, SSD); перезапустите на своём ПК и вставьте свои цифры, добавьте результаты для ключей name и id.*

**Анализ.** C++ быстрее в ~4,6 раза. Слияние в Python медленнее в ~9 раз: на каждую строку выполняются разбор `csv.reader`, создание списка и кортежа, сравнение кортежей в `heapq.merge` и обратная сериализация `csv.writer` — всё это интерпретируемые/объектные операции, тогда как в C++ — сравнение `double` и копирование указателей. Фаза разбиения различается меньше (~2×), потому что в Python сортировка (`sorted`) и чтение строк выполняются кодом на C внутри интерпретатора. Буферизация: увеличение буфера до 1 МБ и запись большими пачками снижает число системных вызовов; число серий k влияет на размер буфера на серию (лимит памяти делится на k) и на глубину кучи log k. Для Python накладные расходы объектов (~120 байт на строку из ~52) заставляют использовать блок всего ~20 % лимита, поэтому серий больше. Строковый ключ сортируется медленнее числового (сравнение строк против `double`).

## 1. Цель работы

Научиться создавать графические интерфейсы на tkinter, организовывать обработку событий и интегрировать ранее разработанные модули в единое приложение; закрепить понимание структуры данных через визуализацию.

## 2. Задание

На основе очереди из лабораторной 4.1 (Pascal, односвязный список на динамической памяти) разработать оконное приложение на Python. Операции со структурой выполняются только через вызовы функций библиотечных модулей (минимум два: C++ и Python). Дополнительно: два варианта C++ модуля (динамическая память и STL). Интерфейс не должен аварийно завершаться при некорректных операциях; визуализация обновляется после каждой успешной операции.

## 3. Архитектура

```
app.py (tkinter)  ->  backends.py (фабрика)  ->  queue_py.py   (Python, связный список)
                                              ->  queue_cpp.py  (ctypes)  ->  queue_dyn.dll/.so  (C++, new/delete)
                                                                          ->  queue_stl.dll/.so  (C++, std::queue)
```

Три реализации имеют единый интерфейс: `enqueue`, `dequeue`, `peek`, `size`, `clear`, `items`, `close`. GUI работает только с этим интерфейсом и не знает, какая реализация используется.

### 3.1. C++ модуль на динамической памяти (`queue_dyn.cpp`)
Перенос логики из Pascal-программы 4.1: узел `Node {data, next}`, очередь `Queue {head, tail, count}`. `Enqueue` добавляет узел в хвост, `Dequeue` удаляет голову и при опустошении обнуляет `tail`, `Clear` освобождает все узлы через `delete`. Функции экспортируются с C-интерфейсом (`extern "C"`), очередь передаётся в Python как непрозрачный указатель (handle).

### 3.2. C++ модуль на STL (`queue_stl.cpp`)
Тот же C-интерфейс, но внутри адаптер `std::queue<int>`. Так как `std::queue` не поддерживает итерацию, для получения содержимого (нужно для отрисовки) обходится копия адаптера. Исключения C++ перехватываются внутри библиотеки, чтобы не пересекать границу C/Python.

### 3.3. Python модуль (`queue_py.py`)
Односвязный список на классах. Пустая очередь сообщается исключением `QueueEmptyError`.

### 3.4. Обёртка ctypes (`queue_cpp.py`)
Загружает библиотеку, задаёт `argtypes/restype`, переводит коды возврата (0 = пусто/ошибка) в исключения Python (`QueueEmptyError`, `MemoryError`, `OverflowError`), проверяет диапазон int32.

### 3.5. GUI (`app.py`)
- Выбор реализации (Combobox), поле ввода, кнопки Enqueue/Dequeue/Peek/Clear.
- Canvas: элементы в виде прямоугольников со стрелками, указатели Front и Rear, подсветка первого элемента при Peek.
- Журнал операций и строка состояния.
- После каждой успешной операции вызывается `redraw()`.

## 4. Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Dequeue/Peek из пустой очереди | Предупреждение «Очередь пуста…», состояние не меняется |
| Пустой ввод | «Введите целое число.» |
| Ввод не числа | ««abc» не является целым числом.» |
| Число вне диапазона int32 | «Число не помещается в 32-битный int.» |
| Clear пустой очереди | «Очередь уже пуста.» |
| Нет библиотеки | Пункт реализации не показывается; при ошибке загрузки — сообщение |
